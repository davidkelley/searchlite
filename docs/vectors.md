# Vector Search

Vector search lets you find documents by **meaning** rather than exact keywords. Instead
of matching the word "automobile", a vector search for "car" finds semantically similar
documents -- even if they never use the word "car" at all.

This works by storing numeric vectors (embeddings) alongside each document. These
embeddings are typically generated by a machine learning model (like OpenAI's
text-embedding or Sentence Transformers) that maps text into a high-dimensional space
where similar concepts are close together.

**When you'd use vector search:**
- A support site where users describe problems in their own words and need to find relevant documentation
- A recommendation engine ("show products similar to this one")
- A RAG (retrieval-augmented generation) pipeline that finds context for an LLM
- Hybrid search that combines keyword precision with semantic understanding

Vector search requires the `vectors` feature flag:

```toml
[dependencies]
searchlite-core = { version = "0.5", features = ["vectors"] }
```

---

## Schema

Add a `vector_fields` entry to your schema with the embedding dimension and distance metric:

```json
{
  "vector_fields": [
    { "name": "embedding", "dim": 384, "metric": "Cosine" }
  ]
}
```

- **`dim`** -- the dimension of your embedding vectors. Must match what your model produces
  (e.g., 384 for `all-MiniLM-L6-v2`, 1536 for OpenAI `text-embedding-3-small`).
- **`metric`** -- distance function. `Cosine` (similarity) or `L2` (Euclidean distance).

Per-field HNSW index settings can be tuned via `hnsw: { "m": 16, "ef_construction": 64 }`;
defaults are used when omitted.

---

## Vector-only search

Find the K nearest neighbors to a query vector. This ignores text relevance entirely
and ranks purely by vector similarity.

```json
{
  "query": {
    "type": "vector",
    "field": "embedding",
    "vector": [0.12, -0.34, 0.56, ...],
    "k": 10,
    "alpha": 0.0
  },
  "limit": 10,
  "return_stored": true
}
```

Documents missing vectors are automatically skipped.

---

## Hybrid search (BM25 + vectors)

The real power of Searchlite is combining keyword search with vector similarity. The
`alpha` parameter controls the blend:

- `alpha = 1.0` -- pure BM25 (text relevance only)
- `alpha = 0.5` -- equal blend of text and vector
- `alpha = 0.0` -- pure vector similarity

```json
{
  "query": { "type": "query_string", "query": "fast search engine" },
  "vector_query": {
    "field": "embedding",
    "vector": [0.12, -0.34, 0.56, ...],
    "alpha": 0.3,
    "k": 50
  },
  "limit": 10,
  "return_stored": true
}
```

This finds documents that match the keywords "fast search engine" AND are semantically
similar to the query embedding. A document about "high-performance indexing" might rank
highly even if it doesn't contain the exact words, because the vector captures the meaning.

The tuple shorthand `["embedding", [0.12, -0.34, ...], 0.3]` also works for quick
experiments.

## Multiple vector fields

Blend candidates across multiple embedding fields or queries. Useful when you have
separate embeddings for different aspects of a document (e.g., title embedding +
content embedding):

```json
{
  "query": {
    "type": "bool",
    "should": [
      { "type": "vector", "field": "title_embedding", "vector": [...], "alpha": 0.0, "k": 30 },
      { "type": "vector", "field": "content_embedding", "vector": [...], "alpha": 0.0, "k": 30 }
    ]
  },
  "candidate_size": 100,
  "limit": 20,
  "return_stored": true
}
```

---

## Tunables

| Parameter | Default | Purpose |
|---|---|---|
| `k` | `limit` | Number of ANN neighbors to retrieve |
| `candidate_size` | -- | Oversampling during ANN search (higher = better recall, slower) |
| `ef_search` | auto | HNSW beam width (higher = better recall, slower) |
| `vector_filter` | -- | Pre-filter applied during vector candidate selection |

Raising `candidate_size` or `ef_search` improves recall at the cost of latency. Start
with defaults and tune only if you see relevant documents missing from results.

---

## Notes

- Responses include `vector_score` alongside `_score` (the blended score) when vector search runs.
- Cosine vectors are normalized automatically; vectors with the wrong dimension are rejected.
- ANN (Approximate Nearest Neighbor) via HNSW is not exact -- it trades a small amount of recall for significant speed. For most applications this is the right tradeoff.
